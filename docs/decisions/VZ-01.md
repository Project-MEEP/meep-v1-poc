# VZ-01: Release gate "vulns at zero" for the first stable long-term release

- **ID:** VZ-01
- **Status:** Proposed (owner goal; the owner confirms the fix-time numbers before the long-term release)
- **Date:** 2026-11-19
- **Owner:** Owner (proposed 2026-11-19)

## Decision

The first stable long-term release ships at "vulns at zero", defined as a release gate:

1. Zero known open vulnerabilities in Meep and all dependencies on the release commit (`cargo-deny` advisories clean). **Started now.**
2. `#![forbid(unsafe_code)]` in all Meep crates. **Started now.**
3. All dependencies audited with `cargo-vet` before the long-term release. *Later.*
4. AI security review on every pull request, part of the `all-green` gate. **Started now; provider chosen in VZ-02 (Claude Code Action, then Codex).**
5. Fuzz targets for every input parser (name entry, address parser, backup import; later card intake), run in CI. *Later.*
6. Pre-release adversarial review: an AI red-team pass plus a threat-model check against the built system; every finding is fixed or recorded as an accepted risk. *Later.*
7. Post-release fix-time targets: critical fixed and shipped through a signed update within 72 hours, high within 14 days. *Proposed numbers; the owner confirms them before the long-term release.*

Also started now: automated dependency-update pull requests (Dependabot for Rust crates and GitHub Actions, daily, and Dependabot security updates).

## What was started (2026-11-19)

- Item 1: `deny.toml` with advisories (vulnerabilities denied, yanked denied, unmaintained direct dependencies denied, no ignores without a written reason and the owner's approval), licenses, bans and sources; the existing `deps` job runs it on every pull request, and a new daily `advisories` workflow re-checks `main` because new advisories appear after a merge.
- Item 2: workspace lint `unsafe_code = "forbid"`, every crate inherits it, and every library and binary crate root starts with `#![forbid(unsafe_code)]`; the `forbid-unsafe` CI job (`.github/scripts/check-forbid-unsafe.sh`) is part of `all-green`.
- Item 4: the `ai-security-review` job and its harness (now `.github/scripts/ai-review-plan.sh` and `ai-review-gate.sh`, VZ-02) are in `all-green`. **Status:** the provider is not chosen, so the harness runs in *report-only* mode and writes a visible warning until the owner picks a provider, adds the secret and sets the repository variable `AI_REVIEW_ENFORCE=true`; from then it fails closed on any pull request that changes source, build or workflow files. Dependabot pull requests cannot read ordinary secrets, so a Dependabot copy of the secret is needed when enforcement starts.
- Dependency updates: `.github/dependabot.yml`.

## Notes

- Dependencies may contain `unsafe` code (for example SQLCipher and the operating-system bindings); item 2 covers Meep's own crates only, and item 3 (audits) is what covers dependencies.
- Principle 11: the provider for item 4 is left to the owner; nothing here assumes a vendor.
- Foundation tasks T001 to T007 and T012 carry the setup steps (the workspace lint, the crate-root attribute, the existing `deny.toml`).
