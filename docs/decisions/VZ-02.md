# VZ-02: AI review of every pull request, two reviewers in sequence

- **ID:** VZ-02
- **Status:** Confirmed
- **Date:** 2026-11-20
- **Owner:** Owner
- **Refines:** VZ-01 item 4 (this settles the provider left open there; principle 11: the owner chose it)

## Decision

1. **Reviewer one (enforcing): Claude Code GitHub Action.** The `ai-security-review` job in `all-green` runs `anthropics/claude-code-action` (pinned by commit hash), authenticated with the repository secret `CLAUDE_CODE_OAUTH_TOKEN` (the owner's Max plan). It returns a structured result; `.github/scripts/ai-review-gate.sh` fails the job on any finding at high or critical. It is report-only (passes with a visible warning) until the owner sets the repository variable `AI_REVIEW_ENFORCE=true`; from then it fails closed, including when the review could not run.
2. **Reviewer two (adversarial): Codex GitHub code review** (the owner's ChatGPT plan). Pull requests open as drafts and are marked ready only after `all-green` passes, which triggers Codex. `AGENTS.md` tells it to act as an adversarial security and privacy reviewer looking for what the first review missed.
3. **Shared rules.** `AGENTS.md` and `CLAUDE.md` carry the same rules between `shared-rules` markers; the `agent-rules` CI job fails if they differ.
4. **Branch protection** requires conversation resolution before merge, so every Codex finding is fixed or explicitly answered.
5. **Non-AI baseline:** GitHub CodeQL (free for public repositories), languages `actions` and `rust`, in `all-green`.
6. **Dependabot:** one grouped weekly pull request per ecosystem for version updates; security updates stay immediate and ungrouped. Routine Dependabot version bumps are excluded from the Codex review (by `AGENTS.md` and by the owner's Codex settings); security updates may still get it.

## Safeguards built into the job

- Uses `pull_request`, never `pull_request_target`: fork pull requests get no secrets and no write access, so the review cannot be turned against the repository.
- The review prompt is read from the **base** commit, so a pull request cannot rewrite its own reviewer; the prompt treats all pull request content as untrusted data.
- The review tools are read-only (`Read`, `Grep`, `Glob`, `git diff|log|show`).
- Dependabot pull requests read Dependabot secrets, so the owner adds a Dependabot copy of `CLAUDE_CODE_OAUTH_TOKEN`; the action is told to accept the `dependabot[bot]` actor.

## Owner actions (not done by the repository)

Add the `CLAUDE_CODE_OAUTH_TOKEN` secret (Actions and Dependabot copies); connect Codex to the repository and keep routine Dependabot pull requests out of its review; set `AI_REVIEW_ENFORCE=true`. **Enforcement must be on before the first v1.0.0-alpha tag** (a VZ-01 condition).

## Known limits

- Workflow changes in a pull request take effect for that pull request; the first pull request that adds the review prompt is not reviewed by it (the prompt is not yet on the base commit).
- Whether Codex honors the Dependabot exclusion in `AGENTS.md` is unverified; the dependable control is Codex's own repository settings. If Codex usage limits start skipping reviews of feature pull requests, the owner should be told (check the pull request for a Codex review after marking it ready).
- Dependabot cannot group across ecosystems, so there are two weekly pull requests, not one.
- CodeQL's Rust support with `build-mode: none` is unverified in this repository until the first Rust pull request runs; a finding about cookie flags may need a written dismissal.
